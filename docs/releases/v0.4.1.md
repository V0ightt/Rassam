# Rassam v0.4.1: small projects get real components

A fix for the first thing you see. In 0.4.0, `rassam init` on a small project drafted a single component for all of it, so there was nothing to put a rule between: the README's own example, `forbid web from importing db`, failed with "I don't know a component called web", and a forbidden import passed the gate.

## Install or upgrade

```bash
npx @v0ightt/rassam@0.4.1 init
```

If you already ran `init` with 0.4.0, update the pins it wrote: `@v0ightt/rassam@0.4.1` in `.mcp.json` and `V0ightt/Rassam@<commit SHA> # v0.4.1` (or `@v0.4.1`) in `.github/workflows/rassam.yml`. To get the new draft, run `npx @v0ightt/rassam@0.4.1 init --force`, which overwrites `.rassam/blueprint.json`; do that only if you have not edited the blueprint yet.

## Fixed

- **Small projects are drafted as layers.** In a repository with at most 40 source files, a folder with two or more subfolders named like layers (`web`, `api`, `db`, `domain`, `ui`, `frontend`, `backend`, `storage` and similar) is split into one component per subfolder, however few files each holds. `src/web`, `src/api` and `src/db` with one file each now draft as `web`, `api` and `db`, and the README's example rule works. A small project with no layer names stays whole, and larger repositories draft exactly as before.
- **Release guide.** `docs/releasing.md` now describes the first manual npm publish as it really goes: `--provenance=false` (provenance only works in CI), two-factor authentication without a USB key, and waiting for npm to show the version before approving the deployment.

## Verify what you run

- This is the first version published by the release workflow with npm trusted publishing, so the npm page shows a provenance statement linking the package to the workflow run that built it. The tarball on npm is byte for byte the `v0ightt-rassam-0.4.1.tgz` attached to this release.
- The release assets include `rassam.mjs`, the same file as `action/dist/rassam.mjs` at this tag, and `SHA256SUMS`.
