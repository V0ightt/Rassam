# Rassam v0.4.0: a merge gate for agent-written code

This is the first release of Rassam as an architecture contract and pull request gate. Version 0.3.0 was a different product (an interactive map of a repository); everything here replaces it.

## Install

```bash
npx @v0ightt/rassam init
```

One npm package, no dependencies, Node 20 or later. `init` drafts `.rassam/blueprint.json` from your code and offers to write the MCP server entry (`.mcp.json`), the contract as rules in `AGENTS.md` (with a pointer from `CLAUDE.md`), and the pull request gate (`.github/workflows/rassam.yml`).

The GitHub Action, pinned to this release's full commit SHA (shown next to the tag on this page):

```yaml
      - uses: V0ightt/Rassam@<commit SHA> # v0.4.0
```

## What it does

- **Judges every pull request by the contract on its base branch.** A pull request cannot loosen the rules it is checked against. Removing a rule, lowering a severity, widening an exception or moving files out of a constrained component fails until a human applies the `rassam:approved` label.
- **Weakened tests need a human.** Skipped or focused tests, removed or always-true assertions, deleted test files, lowered or removed coverage thresholds and forced success exits fail the same way until a human approves them. Other changes to tests, CI and agent configuration are warnings.
- **Only new problems fail**, so it can be adopted on an existing codebase.
- **Rules in prose for every agent.** `rassam instructions --write` states the contract's rules, protected paths and invariants in `AGENTS.md`, with the standing orders: never weaken a test or a check, and stop and report when a task needs a rule broken. `rassam check` says when the block has fallen behind the contract.
- **An MCP server** for agents that want to ask while they work: `explain_path`, `check_dependency`, `impact`, `check_changes`, `architecture_diff`, `system_status`, `report_conflict`, `propose_change`.
- **A live system diagram** for your README, redrawn on every push, and the **Studio**, a web app to read and edit the contract.

## Why

In a 27-run pilot (Opus 5.5, Sonnet 5.5 and Haiku 5.5; no rules, prose rules, or the contract), agents with no rules took a forbidden shortcut every time the owner asked for it (3 of 3), and the gate failed all 4 changes that contained it while passing every honest one. Prose rules steered as well as the contract's query tools, which is why `init` now writes them. The pilot also showed the gate only warned on edited tests; this release makes the strong signals fail until approved. Method and limits: `research_notes/Rassam usefulness and launch readiness/05-pilot-and-hands-on-trial.md`.

The gate's own benchmark, [116 labelled cases](https://github.com/V0ightt/Rassam/blob/main/bench/gate/RESULTS.md): 89.5% of expected findings raised (100% outside the nine hard evasions, which it misses), 48 of 79 attacks now fail the check instead of 31, and none of the 37 legitimate changes fails.

## Upgrading and things to know

- **Strong test-weakening signals are now errors by default** (`policy.verificationWeakening: "require-approval"`). To keep them as warnings, set it to `"warn"`; that edit is itself a contract weakening and needs the approval label on the pull request that makes it.
- **First-run fixes:** one dependency cycle is drawn once, on its edges and in the header, instead of a red badge on every card in it; drafts split standard Java layouts by package, name a Go root package as code, and merge long runs of small sibling folders; violations of a fresh draft's own rules are reported as having existed before the contract did; and a blueprint edit that changes nothing semantic (such as the `$schema` line) no longer puts invariants in scope.
- **Removed:** the classic map workspace at `/map` and the routes and dependencies only it used.
- **License:** Apache-2.0 from this release on. Earlier releases keep the license they were published under.

## Verify what you run

- The tarball on npm is byte for byte the `v0ightt-rassam-0.4.0.tgz` attached to this release, which the release workflow built from this tag. npm can only trust a release workflow for a package that already exists, so this first version was uploaded by hand and has no provenance statement; from the next version on, every release is published by the workflow with npm provenance (`npm audit signatures` checks it).
- The release assets include `rassam.mjs`, the same file as `action/dist/rassam.mjs` at this tag (the release workflow rebuilds it and fails if the committed copy differs), and `SHA256SUMS`.
